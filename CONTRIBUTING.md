# 🛠️ Инструкция по разработке и расширению SQLite функций (MRS Fork)

Этот форк `op-sqlite` содержит кастомные C++ расширения для SQLite. Они решают проблемы с кириллицей (UTF-8), добавляют поддержку регулярных выражений и оптимизируют работу с JSON-путями.

Чтобы проект оставался чистым и расширяемым, все нативные функции спроектированы по паттерну **«Регистратор»** (*Registry / Dispatcher*).

---

## 📂 Архитектура и структура файлов

Весь кастомный код изолирован в папке `cpp/mrs_functions/` и не затрагивает основную логику `op-sqlite`. Вносить изменения в конструкторы `DBHostObject.cpp` **не требуется**.

```text
op-sqlite/
└── cpp/
    ├── mrs_sqlite_functions.hpp    <── Главный Диспетчер (точка сборки)
    └── mrs_functions/               <── Папка с логическими модулями
        ├── mrs_text_extensions.hpp  <── Функции для работы с текстом (LOWER, UPPER, REGEXP, MRS_ILIKE)
        └── mrs_json_extensions.hpp  <── Функции для работы со структурами данных (MRS_JSON_PATH)
```

## 🏷️ Правила именования функций

При добавлении или изменении функций строго соблюдайте следующие правила именования в SQLite:

1. **Переопределение встроенных методов** (`lower`, `upper`): Регистрируются под своими оригинальными именами. Они заменяют стандартное ASCII-поведение SQLite на правильную работу с UTF-8 (кириллицей).
2. **Активация операторов** (`regexp`): Регистрируется строго под именем `"regexp"`. Это активирует встроенный синтаксический сахар SQLite, позволяя писать в запросах `WHERE name REGEXP 'шаблон'` вместо обычного вызова функции.
3. **Кастомные методы** (`mrs_ilike`, `mrs_json_path`): Обязательно используют префикс `mrs_`. Это предотвращает конфликты с будущими обновлениями оригинального SQLite и явно указывает разработчикам на кастомный синтаксис.

## 🚀 Как добавить новую SQL-функцию

Если вам нужно добавить новую функцию (например, для работы с криптографией или датами), выполните 3 простых шага:

### Шаг 1: Создайте или откройте файл модуля
Если функция логически относится к тексту или JSON, откройте соответствующий файл в `cpp/mrs_functions/`. Если это новая группа функций, создайте новый файл (например, `mrs_crypto_extensions.hpp`).

Напишите нативную функцию по стандарту SQLite C-API:

```cpp
#ifndef MRS_CRYPTO_EXTENSIONS_HPP
#define MRS_CRYPTO_EXTENSIONS_HPP

#include "../sqlite3.h"

static void mrs_hash_native(sqlite3_context *context, int argc, sqlite3_value **argv) {
    if (argc < 1 || sqlite3_value_type(argv[0]) == SQLITE_NULL) {
        sqlite3_result_null(context);
        return;
    }
    // ... ваша логика на чистом C++ ...
    sqlite3_result_text(context, "hashed_string", -1, SQLITE_TRANSIENT);
}

#endif // MRS_CRYPTO_EXTENSIONS_HPP
```

### Шаг 2: Подключите и зарегистрируйте функцию в Диспетчере
Откройте файл `cpp/mrs_sqlite_functions.hpp`.
1. Подключите ваш заголовочный файл.
2. Добавьте вызов `sqlite3_create_function` в метод `mrs_register_all_functions`.

```cpp
#include "mrs_functions/mrs_crypto_extensions.hpp" // 1. Подключаем новый модуль

static void mrs_register_all_functions(sqlite3 *db) {
    if (db == NULL) return;
    
    // ... существующие регистрации ...

    // 2. Регистрируем новую функцию mrs_hash (принимает 1 аргумент)
    sqlite3_create_function(db, "mrs_hash", 1, SQLITE_UTF8 | SQLITE_DETERMINISTIC, 0, mrs_hash_native, 0, 0);
}
```

### Шаг 3: Добавьте TypeScript типы
Чтобы у разработчиков работал автокомплит в VS Code, добавьте описание метода в файл описания типов (например, `index.d.ts`):

```typescript
/**
 * Кастомный метод хеширования строк на C++.
 * @param value Строка для хеширования
 */
function mrs_hash(value: string): string;
```

## ⚠️ Памятка по безопасности и производительности

* **Защита памяти:** Всегда освобождайте выделенную память (`sqlite3_free()`). Выделяйте память только через `sqlite3_malloc()` во избежание утечек внутри долгоживущего пула потоков React Native.
* **O(N²) операции:** Избегайте использования `strcat()` в циклах при сборке динамических строк. Используйте паттерн со сдвигом указателя и `sprintf()` / `snprintf()`, это работает в разы быстрее.
* **Пересборка индексов:** Если вы применили этот форк к базе данных, где уже были построены индексы на основе старого встроенного `lower()`, обязательно выполните SQL-команду `REINDEX;` в приложении, иначе поиск по индексам будет игнорировать кириллицу.
